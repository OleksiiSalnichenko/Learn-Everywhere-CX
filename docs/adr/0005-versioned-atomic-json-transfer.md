# 0005. Версійований атомарний JSON-обмін

## Контекст
Користувач має переносити один або кілька словників без доступу застосунку до всього файлового сховища та без ризику часткового імпорту.

## Рішення
Обмін використовує системні `CreateDocument` і `OpenDocument` та зовнішній JSON-контракт із `schemaVersion`. Імпорт повністю читається, перевіряється й показується для підтвердження до однієї транзакції; експорт формує узгоджений знімок і не включає внутрішні UUID, `draftId`, кеш, ключі чи налаштування.

## Чому
Відхилено експорт внутрішньої Room-схеми: він прив’язав би публічний файл до міграцій бази й розкрив технічні ідентифікатори. Відхилено потоковий частковий імпорт, бо помилка наприкінці файлу залишила б бібліотеку в проміжному стані; відхилено широкий доступ до сховища, бо системний picker покриває сценарій із меншими дозволами.

## Наслідки
Формат має явну сумісність, помилки не змінюють базу, а round-trip зберігає текст і порядок. Мінуси: кожну нову версію схеми треба підтримувати або явно відхиляти; повна валідація потребує лімітів розміру; повторний імпорт створює нові словники із суфіксами замість автоматичного злиття.
